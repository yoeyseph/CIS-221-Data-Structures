Hi, we’re Joseph Proper and Seth Flenar. Our project is Fantasy Quest, a small dungeon-style game built for CIS 221. We’ll show how its game logic, data structures, and interface work together.

Fantasy Quest presents a sequence of monster encounters. The player fights, gains currency and sometimes an item, then moves to the next monster. GameAI manages encounters and battles; Player holds the rewards; the Monster interface gives each enemy the same basic methods; Swing provides the GUI.

We use an ArrayList for the player’s three currency totals, a LinkedList for inventory items, and a Queue for monster encounters. The slide says FIFO wasn’t needed, but GameAI does use it: poll() removes the first monster in line, so encounters are fought in order.

A battle begins when GameAI polls the next monster. If the queue is empty, the GUI reports that no enemies are nearby. Otherwise, GameAI adds the monster’s currency to the player’s totals and adds an item when one is available.

This table shows the rewards defined in the code. Skeletons give a Bone Knife, Orcs give an Orc hammer, and Goblins have no item drop. Every monster still adds its gold, silver, and copper values to the player’s currency.

The GUI is built with Swing. The next encounter appears at the top. Fight Battle resolves that encounter, Check Items displays the inventory, Add Monsters queues five random encounters, and New Game resets the player and battle history before adding a fresh set.

Fantasy Quest uses a FIFO queue to drive encounters, GameAI to resolve each fight, and Player collections to keep the rewards. Thanks for listening—what questions do you have?


GUI-only script

The Fantasy Quest interface is built with Java Swing. It shows the next monster, the player’s currency and item count, the latest battle result, and a running battle history. Fight Battle resolves the next encounter and displays its rewards. Check Items shows the inventory, Add Monsters adds five random encounters, and New Game clears the player’s status and history before starting a fresh queue. The layout keeps the main actions at the top and separates the latest update from the battle history.
